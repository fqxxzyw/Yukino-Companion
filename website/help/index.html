桌面端

安装与首次配置

安装程序后，根据对话、翻译和语音功能选择所需资源。

更新于 2026-11 · v0.4.6

入口
桌面端首次配置向导；设置 → 一键配置本地功能
所需信息
Windows x64 安装器；按需准备 API 账号或本地资源
完成标志
软件可启动；选定的对话方式可返回一条回复

配置步骤

  1. 从官网下载区（优先走 dl.yukino.fqxxzyw.cn 国内高速源，保留 GitHub Releases 备用源）下载名字含 Base-Setup 的 Windows x64 基础安装器或便携版。先查看该版本的“验证状态”，测试版不等于稳定版。
  2. 按“完整性检查”核对 SHA-256，再运行安装器。基础安装只解压程序，不在安装过程中拉取模型或 Python。
  3. 打开软件，在首次配置向导选择本地对话、日语翻译、语音合成或桌宠语音。资源和所需环境会分别显示，可以取消、重试或先跳过。
  4. 只想用远程文字聊天时，跳过本地资源，进入设置 → 对话 API，选择服务商并配置密钥。

组件与状态

  • 程序：界面、聊天记录、设置和桌宠窗口。
  • 模型：本地回复、翻译和语音各自需要的权重文件。
  • 环境：应用专用 Python 与本地推理依赖。桌宠预录语音使用音频播放器。
  • 已安装：所需文件已准备好。未加载：模型文件已保存在磁盘，首次使用或手动加载后进入推理内存。

要继续配置，可从设置中的“一键配置本地功能”打开向导。旧安装器 v0.4.0-local.13 在安装过程中下载应用分卷，与基础版的流程不同，请不要混用两种说明。

桌面端

安装文件校验

对照同一 Release 的 SHA-256，确认文件下载完整且与发布资产一致。

更新于 2026-11 · v0.4.6

入口
GitHub Releases → 对应版本附件
输入
待检查文件、同版本可信 SHA-256 清单
输出
文件 Hash 与发布记录一致

核对来源

确认地址属于 github.com/fqxxzyw/Yukino-Companion。下载同一个发行版本的安装器和 SHA256SUMS.txt。不要将别的版本或第三方帖子中的校验值混用。若当前发行尚未提供该文件，可对照该发行的 base-installer.json 或资产清单中的 sha256；没有可信校验值时先在社区反馈，不自行猜测。

在 PowerShell 中检查

打开安装器所在文件夹，在地址栏输入 powershell 并回车，然后执行：

Get-FileHash -LiteralPath '.\Yukino-Companion-0.4.6-Base-Setup.exe' -Algorithm SHA256
Get-Content -LiteralPath '.\SHA256SUMS.txt'

将第一条命令输出的 Hash 与清单中同名文件的 64 位 SHA-256 逐字对照，大小写不影响比较。文件改名时先改命令里的文件名。分卷资源要逐卷对照，不能只校验第一卷。

校验不一致时不要运行该文件；重新下载并再次检查。校验通过只说明文件与可信发布记录一致，不等于代码安全审计，也不代表所有功能都已经通过测试。

系统提示

当前测试安装器未代码签名，Windows 可能显示未知发布者或信誉提示。不要关闭全局防护或直接忽略所有提示；先核对仓库、版本、文件摘要和系统报告，再决定是否继续。无法判断时把不含个人信息的提示截图发到 Bug 区。

桌面端

对话 API 配置

密钥、服务地址和模型必须属于同一个平台；软件主要接入 Chat Completions。

更新于 2026-11 · v0.4.6

入口
设置 → 对话 API
必填项
服务地址（Base URL）、模型 ID；远程服务通常还需 API Key
协议
OpenAI-compatible Chat Completions；按服务商实际支持范围调用
完成标志
测试对话连接成功；实际消息正常返回

配置字段

  • 服务地址（Base URL）：服务商的兼容 API 根地址。软件追加 /chat/completions；填写根地址时保留服务商要求的 /v1 等版本路径。
  • API Key：由相同服务商的账号创建，仅输入桌面端密钥框。
  • 模型 ID：填写账号有权调用且支持对话的精确 ID。
  • 模型列表：通常请求 GET /models；百炼预设使用同源 /api/v1/models，硅基流动按对话类型筛选。

已实现的对话请求

桌面端 electron/chat.cjs 向配置的服务发送 POST /chat/completions，使用 Content-Type: application/json；配置密钥时发送 Authorization: Bearer <API_KEY>。以下为请求结构示例，模型名是需要替换的占位符：

{
  "model": "<账号可用的模型 ID>",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}

流式响应读取 choices[0].delta.content；JSON 响应读取 choices[0].message.content。这是桌面端调用服务商的协议，社区网页只读取公开社区内容。

验证步骤

  1. 设置 → 对话 API → 选择服务商。
  2. 只在软件的密钥输入框粘贴 API Key，不要发送到聊天或社区。
  3. 点击“验证密钥并获取模型”，从账号返回的候选列表选择模型。
  4. 点击“测试对话连接”。成功后发送一条短消息验证；测试可能计入供应商用量。

获取模型列表成功不保证每一个模型都有调用权限或支持本软件需要的参数。列表接口不受支持时，软件会明确提示尚未验证；可按服务商官方文档在高级设置填写模型，再测试实际对话。不要把“输入了密钥”当作已经验证成功。

DeepSeek

登录 DeepSeek 开放平台，进入 API keys 页面创建并保存自己的密钥。在软件中选择 DeepSeek，基础地址使用 https://api.deepseek.com。模型以账号列表和当前官方文档为准，不在本帮助页固定容易过时的型号。

DeepSeek 官方接入文档 · 开放平台

通义千问 / 阿里云百炼

在百炼或 Model Studio 控制台选择所在地域和工作空间，进入 API Key 页面创建普通按量 API 密钥。地域的密钥、服务地址和模型不能混用；Token Plan / Coding Plan 有独立规则，不能直接当作普通按量接口。

软件提供北京与新加坡预设。若控制台显示工作空间专属 API Host，请在高级设置按官方文档替换为该工作空间的 OpenAI-compatible 地址。以控制台给出的地域与 Host 为准。

官方密钥创建说明 · OpenAI 兼容接口

硅基流动

登录 SiliconCloud，进入“API 密钥”创建密钥。在软件中选择“硅基流动”，基础地址使用 https://api.siliconflow.cn/v1，然后获取账号的对话模型列表。图像、语音、嵌入和重排模型不等于可聊天的模型。

硅基流动快速上手 · 控制台

Google Gemini

在 Google AI Studio 创建或查看 Gemini API Key，并确认账号、项目、地域和配额满足官方要求。在本软件中选择“自定义兼容服务”，基础地址填 https://generativelanguage.googleapis.com/v1beta/openai/，再获取模型并测试。不要填 Gemini 原生 generateContent 接口；本软件使用它的 OpenAI 兼容层，兼容层的功能范围不等于完整原生 API。

创建 Gemini API Key · Google 官方兼容说明

OpenAI

在 OpenAI API 平台选择项目，创建具有所需调用权限的 API Key，按需要配置 API 账单。在软件中选择 OpenAI，基础地址使用 https://api.openai.com/v1，选择支持 Chat Completions 的对话模型并测试。

ChatGPT 订阅与 API 平台账单分开，不能把 ChatGPT 订阅额度当成这里的 API 额度。本软件当前并未实现 OpenAI 所有接口；仅支持 Responses 的模型或功能不能只换名字就直接使用。

OpenAI 官方快速开始 · 订阅与 API 账单说明

其他服务

Kimi、智谱和自建兼容服务可以从对应预设或自定义地址接入。远程地址应使用 HTTPS；本机服务可以用 localhost / 127.0.0.1。Anthropic 原生 Messages 协议不是 Chat Completions；需要使用明确兼容的接口。

不要把完整密钥写进 Base URL、模型名称、截图或公开仓库。怀疑泄露时，到供应商控制台撤销并重新创建。

桌面端

资源下载与故障处理

查看失败阶段，检查资源来源和磁盘空间，再取消或重试相应任务。

更新于 2026-11 · v0.4.6

入口
首次配置向导；对应功能的资源设置
检查项
资源名称、下载阶段、错误信息、可用磁盘空间
操作
取消、重试；按清单使用已登记来源

先看当前状态

“下载中”显示实际收到的数据；“校验中”会读取已下载文件；“解压中”主要依赖磁盘，网速归零不一定是卡住。检查磁盘可用空间，预留压缩包、解压目录和临时文件的空间。

多连接与备用源

大型资源优先使用内置 aria2，多连接和断点续传无需另外安装 Motrix。速度受 GitHub、原模型源、网络和磁盘限制，不保证固定提速。源站不支持分段、连接受限或 aria2 无法完成时，可以回退普通 HTTPS。

同一文件的主源和备用源都必须匹配清单中的长度与 SHA-256。发生连接超时或源不可用时，下载器尝试已经登记的其他来源；如果用户主动取消，则停止任务，不自动继续换源下载。没有可用备用地址的文件会保留错误并允许重试，不假装换源成功。

可以依次检查

  1. 在浏览器打开资源卡或发行页中的官方链接，确认 GitHub / Hugging Face 是否能访问。
  2. 检查网络与代理。浏览器能访问不代表下载子进程使用相同代理；软件不自动读取或复制浏览器扩展的凭据。调整系统或代理工具配置后重启软件再试。
  3. 若一个源失败，让程序尝试已登记备用源；仍失败时取消后重试，已经校验好的资源不会重复下载。
  4. 检查磁盘空间、文件夹写入权限及系统防护是否阻止文件写入，不要为下载而关闭全局防护。
  5. 暂时不需要本地功能时可以跳过，先用 API 文字聊天。

手动获取文件

只使用项目 Release 或清单明确列出的原作者固定版本链接。按“完整性检查”核对长度与 SHA-256，再使用对应设置里的自定义路径：本地对话选择含 manifest.json 和对应 GGUF 的模型目录；翻译选择匹配模型清单的目录；语音分别选择 GPT、SoVITS 与参考音频。

不要把任意 Python ZIP 当作本应用环境，也不要随便覆盖应用缓存。环境安装没有通用“任意压缩包导入”保证；若自动安装失败，可提供已经安装且依赖兼容的 Python 路径，或携带脱敏错误在社区寻求帮助。

提交有效反馈

附上应用版本、Windows 版本、选择的资源名称、失败阶段、错误代码、是否使用代理以及大致可用磁盘空间。可以附资源卡截图，但隐藏用户名路径、密钥、聊天正文和个人记忆。不要上传整个用户数据文件夹。

桌面端

本地模型与运行环境

准备文件和启动推理是两步；实际设备以加载结果为准。

更新于 2026-11 · v0.4.6

入口
设置 → 本地模型；首次配置向导
资源
对话 GGUF、Hy-MT2 翻译、GPT-SoVITS 语音组件
状态
下载 → 校验 → 安装 → 加载 → 推理
设备
以模型加载后显示的实际 CPU / GPU 为准

组件用途

  • 本地对话模型：1.5B 角色 GGUF，生成角色回复。
  • Hy-MT2 翻译模型：生成日文译文，用于明确选择的本地翻译和内置本地对话流程。
  • GPT-SoVITS 权重：GPT / SoVITS 配对音色文件，用于语音合成。
  • BERT / HuBERT：语音合成的文本与音频特征模型。
  • 公共运行环境：应用专用 Python 和本地模型所需的推理依赖。

准备与加载

  1. 在首次配置向导勾选需要的功能，查看对应资源和运行环境。
  2. 等待每项资源下载、校验和安装完成。
  3. 使用本地回复、补译或朗读时加载对应模型；在状态区确认加载结果和实际设备。

各模型分别占用内存。释放某个模型后，可在对应功能状态中确认；其他已加载模型继续保持自己的状态。

CPU / GPU

首次配置显示当前发行实际提供的环境包。CPU 环境使用 CPU 推理；兼容 GPU 环境配置完成后，设备“自动”才会尝试 GPU。显存不足时可按设置回退 CPU。请分别检查显卡检测、环境安装和模型实际运行设备。

自定义 Python 路径需要具备对应组件依赖。模型加载后如出现人物事实错误、语气偏差或长对话质量下降，可记录输入与版本并反馈模型效果；文件完整性通过 SHA-256 单独检查。

上一篇资源下载与故障处理下一篇日语翻译与语音合成

桌面端

日语翻译与语音合成

按选择的翻译方式准备日文，再使用 GPT-SoVITS 合成语音。

更新于 2026-11 · v0.4.6

入口
设置 → 翻译；设置 → 声音
输入
中文或中日双语回复；语音权重与参考音频
输出
中文 / 日文气泡；日语合成语音
API 模式
双语回复与缺失日文补译均使用当前对话 API

翻译方式

  • API 返回双语 · API 补译：对话请求返回中日双语。缺少日文或点击“补译日文”时，使用当前选中的对话 API；需要有效的地址、模型和密钥，调用可能计入服务商用量。
  • 本地翻译：使用 Hy-MT2 和本地运行环境。使用前在资源向导准备翻译模型与依赖。
  • 内置本地对话：角色模型生成回复后使用本地翻译生成日文。

气泡的中文、日文、双语开关控制阅读内容。语音合成使用准备完成的日文；翻译失败时保留中文与错误提示，先修复翻译配置再朗读。

音色配置

  1. 在资源向导准备公共运行环境、BERT / HuBERT、默认 GPT e2 / SoVITS e1 及参考声音。
  2. 使用自定义音色时，在声音设置选择匹配版本的 .ckpt 和 .pth 文件。
  3. 选择清晰的 3–10 秒 WAV / FLAC 参考音频，填写该音频实际说出的原文及语言。
  4. 保存后试听一小句日语，确认正常后开启自动朗读。

GPT 与 SoVITS 权重需要配对，训练轮次供识别版本使用。参考文本用于描述参考音频的内容。

状态与故障处理

  • 缺少日文：检查当前翻译方式。API 模式检查对话配置和额度；本地模式检查 Hy-MT2 与运行环境。
  • 合成失败：检查两种权重、公共模型、参考音频和对应原文。
  • 合成完成但无声：检查应用与系统输出音量及输出设备。
  • 停止朗读：取消后续播放；中止正在推理的语音可能释放本应用推理进程，下次使用时重新加载。

Bug 与建议

公开下载链接仍由投稿者提供，先核对许可、版本、摘要与来源；外部资源不是项目官方担保。可以在 GitHub 评论中要求作者补充缺失的文件信息。

详情与评论

GET /repos/fqxxzyw/Yukino-Companion/issues/{issue_number}
GET /repos/fqxxzyw/Yukino-Companion/issues/{issue_number}/comments?per_page=30

issue_number 是正整数内容编号，取自列表的 number。详情返回一个 Issue 对象；评论返回数组，包含 user、created_at 与 body。这些接口由 GitHub 提供。

可运行的只读示例

curl -H 'Accept: application/vnd.github+json' \
  'https://api.github.com/repos/fqxxzyw/Yukino-Companion/issues?state=all&sort=created&direction=desc&per_page=60'

示例只读取公开数据，无需提供密码或令牌。本文不提供虚构的本站注册、登录或发布接口；发布入口打开 GitHub Issue 表单。

分页与状态

  • 下一页：读取响应头 Link 中 rel="next" 的地址；页面将分页请求限制在本仓库 GitHub API 路径。
  • 403 / 429：显示访问受限提示，可稍后刷新或在 GitHub 查看。
  • 404：内容不存在、已删除或暂不可公开访问。
  • 请求超时：单次请求等待最多 15 秒，然后允许重试。
  • 切换页面：中止旧详情和评论请求，避免较早的结果覆盖当前页面。
