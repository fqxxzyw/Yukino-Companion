# 云端长期记忆

## 保存什么

- 默认 **关闭**。用户在桌面的“个人记忆”里开启“同步当前角色的文字记忆”或“同步纯文字聊天记录”后才会上传。
- 只保存文字：角色 ID、账号 ID（服务端从登录会话取得）、记忆文本、版本、时间；聊天另存会话 ID、角色、文本和时间。
- 不上传语音、图片、视频、附件、模型、`state.json` 或 API 密钥。
- 不批量上传旧聊天；聊天同步是用户在面板里主动点击“上传最近文字对话”。
- D1 中是明文 UTF-8。**没有实现端到端加密**，能访问 D1 的运维方可以读取文本。

## 数据表

`0004_cloud_memory.sql`：

- `cloud_memories`：`PRIMARY KEY(user_id, character_id)`，保存一个角色的一份文字记忆、`version`、`updated_at`、`deleted_at`。
- `cloud_memory_settings`：每个账号的 `sync_memory` / `sync_chat` 开关，默认 0。
- `cloud_chat_messages`：`PRIMARY KEY(user_id, id)`，按账号、角色、会话和时间索引，仅 `user` / `assistant` 文本。

迁移只新增表和索引，不删除、不重建现有用户、会话、进度或皮肤表。

## 同步行为

- 读取和写入都以 Bearer access token 的服务端会话为准；客户端不能指定其他用户 ID。
- 同一角色记忆按版本同步：客户端提交 `baseVersion`，与服务端版本不一致时返回 `409 memory_conflict` 和云端文本，不静默覆盖。用户可以在面板中查看云端版本后选择覆盖或先恢复/合并。
- 写入使用版本比较交换：两台设备同时提交同一个 `baseVersion` 时只有一个成功，另一个收到冲突，不会静默丢写。
- 没有改动就不产生写入；相同聊天消息按 `(user_id,id)` 幂等，重复上传不会重复计数；在 2000 条上限处重试已保存的批次仍然成功，只有真正新增的消息才占额度。
- 云端记忆不会自动进入提示词。只有用户点击“从云端恢复”写入本机记忆后，才按本机原有逻辑随对话发送给模型；云端聊天只用于查看/恢复，不会自动注入全部历史，因此不会因为同步聊天而额外消耗模型 token。
- 断网、超时、429 或 5xx 只提示失败，本地记忆和本地聊天照常保留，待联网后手动重试。
- 删除云端记忆/聊天是软删除，不删除本机聊天或记忆。
- 云端对话上限 2000 条/账号；超限返回 413 并继续保留本地数据，不自动删除用户记录。

## 在桌面端开启

1. 打开“个人记忆”。
2. 在“云端长期记忆”中开启“同步当前角色的文字记忆”。
3. 点击“上传当前记忆”；在另一台设备登录同一账号，打开个人记忆，点击“从云端恢复”。
4. 如需同步纯文字聊天，再开启“同步纯文字聊天记录”，选择会话后点击“上传最近文字对话”。
5. 查看/删除：面板中的“查看云端记忆”“查看云端对话”“删除云端记忆”“删除云端对话”。删除云端内容不影响本机。

## 额度估算

D1 免费额度为单库约 500 MB，和账号/进度共用。

- 一份角色记忆上限 12,000 字符；中文按 UTF-8 约 3 字节/字。典型 1,000–5,000 字符约 3–15 KB（含索引/行开销）。
- 聊天单条上限 4,000 字符，账号上限 2,000 条；满载理论约 8 MB/账号，实际通常远低于此。
- 以每账号 9 个角色、每角色 5 KB 记忆估算，约 45 KB/账号；500 MB 可容纳约 1 万级账号的记忆摘要，但聊天和现有数据会共享同一额度。
- 读取使用按角色/时间的索引和分页；列表每页最多 50 条，聊天每页最多 50 条，不做全表扫描。

这些是容量估算，不等于已经压测过 D1 的写入/读取日额度；上线后应以 Cloudflare 的实际用量为准。

## 未验证 / 限制

- 0003/0004 已应用到生产 D1 `yukino-account`，但尚未跑真实多设备同步；本地 Node D1 测试已覆盖版本冲突、账号隔离、幂等聊天、额度边界和删除，生产库备份副本上的迁移彩排已通过。
- 面板已在 `qa:account` 中用确定性桌面桥验证开关、恢复、上传和查看云端对话；尚未通过真实 Electron IPC 连接生产 API 验证。
- 桌面端目前是手动上传/恢复，不是每次对话后台自动推送；自动同步需要进一步接入主进程保存钩子。
- 没有端到端加密；敏感内容不应开启同步。
- 没有实现付费额度扩容或自动清理；达到 D1 额度时必须由用户删除云端内容或由运维扩容。
