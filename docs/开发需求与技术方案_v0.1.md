## 1. 产品定位与两项交付物

### 1.1 桌面软件

**[确认]** 以雪之下雪乃为核心角色的数字人软件。提供文字对话、本地语音回复、动态人物展示、窗口模式与桌面人物模式。本地语言模型和云端 API 都可使用；支持跨 API 保留软件侧记忆。

目标体验：用户打开软件，能够与具有设定性格和知识的雪乃聊天；她用指定音色回答，人物随语音和对话状态表现出相应动作。

### 1.2 公共资源社区

**[确认]** 社区与 EXE 是两个独立产品，社区用于分享音色包、人物资源和相关内容。文件可以通过网盘链接分享，也允许用户主动公开联系方式，供其他人私下联系。

**[建议]** 社区通过浏览器访问；桌面软件提供“资源社区”入口，但不把整个社区作为本地软件运行的前提。软件不要求登录社区才能聊天、加载人物或使用本地音色。

### 1.3 二者关系

| 项目 | Windows EXE | 公共社区网站 |
|---|---|---|
| 核心目标 | 聊天、语音、人物陪伴 | 发布、发现、交流、下载资源 |
| 数据 | 本机聊天、记忆、API 配置和资源 | 公开帖子、资源说明、评论和用户资料 |
| 账号 | 建议不强制登录 | 投稿与评论需要社区身份 |
| 模型推理 | 本地或用户配置的 API | 首期不提供在线模型推理 |
| 文件导入 | 本地导入、验证、应用 | 提供外部下载链接和兼容说明 |
| 更新 | 安装程序及组件更新 | 网站独立发布与更新 |
| 隐私边界 | 私有数据默认留在本地 | 只有用户主动提交的内容才公开 |

**[建议]** 社区不可访问时，已安装资源和本地软件照常运行。社区账户注销不自动删除本机聊天；卸载桌面软件也不删除社区账号。

## 3. 技术栈与工程边界

### 3.1 桌面软件建议技术栈

下表为 **[建议]**，不是用户已选定的技术。选择目标是统一开发聊天 UI、透明人物窗口与本地推理管理。

| 层 | 建议技术 | 职责与说明 |
|---|---|---|
| 桌面容器 | Electron + TypeScript | 无边框主窗口、独立透明人物窗口、托盘、快捷键、屏幕捕获、进程管理 |
| 界面 | React + TypeScript + Vite | 聊天、设置、资源管理和交互状态 |
| UI 基础 | CSS Variables + CSS Modules，必要时使用 Radix Primitives | 自定义设计，避免套用未经调整的组件库外观 |
| 动效 | CSS transitions；需要弹性时采用 Motion | 侧边栏、面板、切换动画；统一响应减少动态效果 |
| UI 状态 | Zustand | 窗口、展示和会话 UI 状态；数据库仍为持久数据来源 |
| 本地数据库 | SQLite，主进程独占数据库写入 | 会话、消息、记忆、知识索引元信息、资源与迁移版本 |
| 数据校验 | Zod 等显式 schema 校验 | 设置、资源包、IPC 和模型结构化输出 |
| 3D 渲染 | Three.js + @pixiv/three-vrm | 优先接入 VRM；普通 GLB 只作为能力较少的候选 |
| Live2D | 官方 Cubism SDK for Web 的独立适配器 | 分别处理模型、表情、动作、口型；正式采用时核对 SDK 分发条件 |
| 旧桌宠 | 单独 LegacyPetAdapter | 根据真实素材或工程决定精灵图、视频或外部程序适配方式 |
| 本地 LLM | llama.cpp / llama-server + 兼容 GGUF | 推理服务；与桌面程序通过本机接口通信 |
| 语音推理 | GPT-SoVITS + 独立 Python 运行环境 | 作为受控本地子进程，不要求用户安装 Anaconda |
| 音频 | Web Audio API | 队列播放、停止、音量分析和基础口型驱动 |
| 截图 | Electron 屏幕捕获能力 + 平台适配 | 屏幕、窗口、区域选择；验证多屏与 DPI |
| 密钥 | Windows 安全存储，通过主进程使用 | 不放到明文数据库、日志、导出包或前端持久存储 |
| 构建发布 | electron-builder（候选）+ Windows CI | EXE 安装包、组件清单、版本信息、校验值 |
| 测试 | Vitest + Playwright，Windows 实机测试 | 状态/队列测试、关键 UI 流程、真实桌面行为验证 |

选择 Electron 的理由是它能够把聊天界面和网页人物渲染放在同一技术体系，并具备无边框与透明窗口能力。[S1][S2] 但透明窗口、最大化、任务栏和鼠标穿透的组合必须先在 Windows 实测，不以 API 存在代替体验验证。

**不将整个主窗口做成透明窗口。** 主窗口使用无边框但正常背景；桌面人物使用独立透明窗口，降低透明渲染的兼容风险。

### 3.2 社区建议技术栈

| 层 | 首期建议 | 完整社区候选 |
|---|---|---|
| 展示网站 | React + TypeScript + Vite，静态构建 | 可沿用 |
| 托管 | GitHub Pages | Pages 保留前端，动态后端另外部署 |
| 投稿与讨论 | GitHub Discussions，浏览器跳转投稿 | 独立登录、投稿 API、评论、审核后台 |
| 公开资源索引 | 构建时生成静态 JSON | 数据库实时查询 |
| 数据服务 | 首期不自建用户数据库 | Supabase Auth/PostgreSQL/RLS + 服务端函数，或自建后端 |
| 大型文件 | 网盘、作者自己的 Releases 或模型托管服务 | 仍以外链为主，必要时增购对象存储 |
| 发布流水线 | GitHub Actions 静态构建 | 独立前后端部署流水线 |
| 社区与软件联系 | 资源清单格式、版本说明 | 可增加确认后导入的应用链接 |

**[待定]** 社区使用“GitHub 账号投稿”还是独立账号，需要用户选择。不能把 Pages 静态托管误写为能够独立运行数据库、私信和任意用户上传服务。[S5]

### 3.3 工程组织建议

建议将代码组织为可独立发布的三个部分：

- desktop：桌面端，包含主进程、preload、聊天渲染器、人物窗口。
- community：公共社区网站与构建流程。
- schemas：共享的资源元信息、兼容性清单与类型定义，不共享用户私人数据库。

语音运行环境、语言模型、训练数据和大模型权重不直接塞进前端源码仓库。训练脚本可以单独放在 training 目录或仓库，不作为普通用户运行软件的必要步骤。

## 4. 桌面界面与布局细则

### 4.1 视觉方向

**[确认]** 不显示传统的异色系统标题栏，界面参考 ChatGPT 桌面端，简单、有高级感。

**[建议]** 顶部保留一体化拖动区和右上角最小化、最大化、关闭按钮；背景与正文统一。颜色、具体圆角、玻璃材质强度尚未定稿，不默认做成重玻璃或大面积渐变。

正文以可读性为先；人物展示突出角色，操作按钮平时克制。状态不只用颜色区分，还提供文字或图标。键盘焦点可见。

### 4.2 页面区域

| 区域 | 元素 | 布局要求 |
|---|---|---|
| 侧边栏 | 展开/收起、新聊天、历史、搜索、功能入口、右下角设置 | 固定于窗口左侧；展开时参与布局，不覆盖桌面宽屏主内容 |
| 人物区 | 人物画布、少量悬浮控制 | 左右可换；不与消息滚动绑定 |
| 聊天区 | 会话信息、消息、输入框 | 占剩余空间；输入框固定在聊天区底部 |
| 顶部 | 拖动区、会话/模型必要状态、窗口控制 | 不出现异色标题带 |
| 全局浮层 | 设置、资源导入、错误详情 | 不因为人物渲染层而被遮挡 |

草图只给出三栏结构，没有确定输入框尺寸、完整色板或顶部具体信息，这些属于后续设计稿内容。

### 4.3 宽度与收起规则

**[建议默认值，仅供首轮设计]**

- 侧边栏展开约 248px，收起为约 48px 的窄栏，保留展开入口和设置入口。
- 人物区优先使用剩余内容区约 28% 的宽度，并受最小/最大宽度约束；初始建议 240–420px。
- 聊天列保留可读最小宽度约 360px；不足时先压缩人物区、再自动收起侧边栏。
- 极窄窗口用头像/紧凑人物模式替代完整人物列，提供一键恢复；不挤压输入框到无法使用。
- 具体阈值经 Windows DPI 与字体缩放验证，不直接当成最终视觉规范。

### 4.4 侧边栏与人物左右布局的联动

| 当前布局与操作 | 应发生的结果 |
|---|---|
| 侧边栏展开、人物靠左 → 收起侧边栏 | 主内容左边界随窄栏向左移动；人物立即重新靠齐新的内容区左侧，不保留原侧边栏宽度的空白；聊天区接在人物右侧 |
| 侧边栏收起、人物靠左 → 展开侧边栏 | 侧边栏占用真实布局宽度；人物与聊天一起向右重新排布，不被侧边栏覆盖 |
| 人物靠右 → 收起侧边栏 | 人物继续靠主内容右边界；新增空间主要归聊天区，聊天左边界向左扩展 |
| 人物靠右 → 展开侧边栏 | 人物仍在右侧；聊天可用宽度缩小，不把人物推到窗口外 |
| 人物由左切右 | 人物列与聊天列换序；输入框仍属于聊天列；消息和滚动位置保持 |
| 隐藏人物 | 人物列移除，聊天区释放该空间；恢复时按之前的左右选择重新出现 |
| 拖动人物列分隔线 | 调整人物列占比并保存；不得压缩聊天到最小宽度以下 |
| 主窗口最大化/还原 | 基于新容器重新计算布局，不沿用旧屏幕坐标 |
| 调整 Windows 显示缩放或切换显示器 | 依据逻辑像素重新计算，人物不裁切、输入框不越界 |
| 设置面板打开期间收起侧边栏 | 设置面板相对窗口定位，不因侧边栏宽度变化产生漂移 |

“靠左”指 **可用主内容区域的左边缘**，不是穿过仍存在的窄栏贴到屏幕最左边。若用户希望完全隐藏侧边栏，则左边界变为窗口内容边缘，展开按钮改为顶部悬浮入口，此变体待确认。

实现建议：以 Grid/Flex 正常布局控制区域，不用把人物写死在固定 left 像素位置。画布通过 ResizeObserver 更新尺寸与相机；不能在每一帧侧边栏动画中重载模型。

### 4.5 动画与滚动

- **[建议]** 侧边栏过渡约 180–260ms，内容跟随布局变化；不突然跳位、不强弹跳。
- 收起和展开不重建聊天、不清空输入草稿、不切换会话。
- 用户正在底部阅读时，流式消息保持在底部。
- 用户向上滚动后，停止强制滚到底部，显示“回到最新”按钮。
- 人物列不随消息滚动；输入框始终在聊天区域底部。
- 减少动态效果开启时，移除布局位移动画与非必要人物大动作。

### 4.6 窗口与桌面模式

| 操作 | 建议行为 |
|---|---|
| 点击“桌面模式” | 隐藏主窗口，显示独立透明人物窗口；当前会话、音频队列和记忆不重置 |
| 从桌面人物打开聊天 | 恢复主窗口与原会话，默认隐藏桌面人物窗口，避免双人物与双份声音 |
| 点击关闭按钮 | 首次询问后记住选择：保留桌面人物 / 收至托盘 / 完全退出 |
| 点击最小化 | 最小化主窗口，不自动等同桌面模式 |
| 完全退出 | 停止截图、音频和生成；保存数据；结束由本软件启动的子进程 |
| 崩溃后重启 | 恢复会话与布局；不自动恢复持续屏幕共享 |
| 从睡眠唤醒 | 检查设备与服务状态；屏幕观察仍暂停，等待用户再次开启 |

### 4.7 桌面人物操作

- **[建议]** 拖动人物调整位置；设置缩放、置顶、锁定位置、鼠标穿透。
- 桌面位置与窗口人物左右布局分别保存，互不覆盖。
- 每台显示器保存位置；断开显示器后，把人物移回可用屏幕。
- 托盘提供“找回人物”，修正屏幕外坐标。
- 点击人物可弹出紧凑输入框；右键菜单包含打开聊天、静音、换装、设置、隐藏、退出。
- 透明区域鼠标穿透与人物区域交互分开验证，不能仅因窗口透明就宣称透明区域不挡点击。
- 全穿透模式下，托盘和快捷键必须能恢复交互。
- 建议首期不做自由走动、自动爬窗口等未讨论功能。

## 5. 聊天功能与交互

### 5.1 输入框

**[确认]** 参考 ChatGPT 桌面端；**[建议]** 多行输入、自适应高度、有上限后内部滚动。

- Enter 发送，Shift+Enter 换行，可在设置中交换。
- 中文输入法候选状态下 Enter 不误发送。
- 输入为空时不能发送，已选择图片但无文字时可依模型能力发送。
- 生成过程中发送按钮变为停止；输入框可继续编辑下一条草稿。
- 每个会话独立保存未发送草稿。
- 支持复制粘贴文本；图片粘贴只在已支持且明确展示附件时上传。
- 附件入口、屏幕识别入口、语音开关和模型选择保持克制，不把全部高级参数放进输入框。
- 语音输入属于待定扩展，不将 GPT-SoVITS 当成语音识别器。

### 5.2 消息

- **[建议]** 区分用户与角色消息；支持基本 Markdown、代码块、复制、时间、重新生成、朗读。
- 角色真正说出的内容与内部动作标签分离；不显示原始 JSON 指令。
- 重生成从目标回复处分叉或明确替换；不得静默丢掉后续对话。首期建议只允许重生成最后一条回复。
- 请求失败保留用户提问，提供重试；失败不是有效记忆来源。
- 停止生成后保留已生成内容并标记“已停止”，不会误标为完整回答。
- 语音失败时文字回答仍可保留、复制与重试朗读。
- 流式中断重试不会重复插入同一条消息。

### 5.3 会话与侧边栏

- 新聊天、历史列表、搜索、重命名、删除、置顶（建议）。
- 会话搜索先做本地，不向社区上传。
- 删除会话明确提示是否关联处理从该会话提取的记忆；不默认清空所有长期记忆。
- 会话标题可以先用首条提问生成；模型自动命名可选，避免额外 API 调用没有提示。
- 切换会话默认暂停/停止旧会话的自动朗读；具体是否让旧请求后台完成作为设置或后续决定。
- 功能入口建议包括：角色/形象、音色、知识与记忆、资源社区；最终数量待视觉稿确认。
- 当前使用的模型和语音状态要容易发现，不长期占用大块界面。

## 6. 人物、动作、换装与旧桌宠

### 6.1 人物路线

**[确认]** 先试 Tripo 生成 3D；如果视觉效果或制作成本不合适，可改为 Live2D。也可以将两类资源保留为可切换形象。

- Tripo 是外部制作工具，不作为普通用户运行软件的必需服务。
- 生成结果须检查脸部还原、手部、头发、拓扑、贴图、骨骼和表情；自动绑骨不等于完整数字人。
- 3D 初版优先标准化为 VRM；必要时 Blender 修整、骨骼设置与导出。
- Live2D 需要独立分层原画和制作，不能承诺直接由 3D 一键转成等价成品。
- 一套角色设计参考可以共用；3D 和 Live2D 的运行资源分别制作。

### 6.2 统一人物接口

**[建议]** 上层只调用语义能力，不写死某个模型内部参数名：

| 能力 | 含义 |
|---|---|
| load / unload | 校验并加载/释放人物资源 |
| setState | idle、thinking、speaking、paused |
| setExpression | 映射到模型已提供的表情 |
| playMotion | 播放模型支持的动作 |
| setLipSync | 根据实际音频播放进度更新嘴部 |
| setLookAt | 在适度范围内看向鼠标或前方 |
| setOutfit | 切换预先声明的服装或整套形象 |
| resize | 容器变化后更新画布、相机或缩放 |
| getCapabilities | 声明口型、动作、换装等支持情况 |

普通 GLB 没有表情或人形骨架时，仅开放可实现的展示能力；不虚假显示“口型就绪”。

### 6.3 动作状态与优先级

- 待机：轻微呼吸、自然眨眼；不持续重复大幅动作。
- 思考：等待回答时触发轻微动作，超时不无限快速重复。
- 说话：音频真正开始播放时进入；播放结束或停止时闭嘴。
- 表情：从受控集合选择，例如中性、微笑、疑惑；强度可调。
- 优先级建议：用户手动操作 > 语音状态 > 对话动作 > 待机。
- 用户拖动人物期间暂停鼠标视线跟随，避免争夺姿态。
- 缺少动作时回退到中性待机，聊天继续。
- LLM 只能选择允许的动作 ID，不能输出可执行脚本或任意资源路径。
- 换形象时默认等当前语音结束；立即切换需要同步停止旧音频与动作。

### 6.4 换装

**[建议首期]** 整套模型/形象切换：校服、便服、冬装分别为资源变体。使用同一个角色身份、人设、音色及记忆。

后续模块化换装需要统一骨骼、蒙皮、遮挡与兼容组合；不把所有服装都假设为通用。界面只展示已安装且兼容的服装。

更换形象保留用户选定的布局和缩放偏好，按新模型边界适度修正；加载失败保留原形象，不留下空白窗口。

### 6.5 旧桌宠

**[确认目标；实现待检查]** 用户之前制作过桌宠，希望可以接入。

- 首先获取旧桌宠工程或素材及动画清单，确认是精灵图、视频、Live2D、3D 还是独立 EXE。
- 精灵图可映射待机、说话等有限状态；不承诺精确口型。
- 只有独立 EXE 且无接口时，不视为已能内嵌；可研究外部启动联动，或从源码移植。
- 资源不支持的能力在设置里隐藏或说明，不出现可点击但无效果的按钮。
- 本文不将历史上的具体桌宠项目自动认定为此次接入对象。

## 7. 语言模型、人设、知识与微调

### 7.1 两种对话来源

| 模式 | 工作方式 | 切换约束 |
|---|---|---|
| 本地 | 兼容 GGUF 模型由受管进程加载 | 检查文件、上下文模板、运行设备与可用内存 |
| API | 用户配置服务地址、密钥与模型 | 不假设所有提供商都完全兼容同一协议 |

**[建议]** 第一批支持 OpenAI-compatible 协议适配，再按需求增加其他供应商原生协议。切换 API 保留会话和记忆，但需重新构建符合目标模型能力的上下文。

每个配置记录：名称、服务地址、密钥引用、模型名称、文本/视觉/流式/结构化输出能力、超时、上下文预算。能力通过配置与小测试确认，不能仅靠模型名猜测。

### 7.2 上下文构建

一次请求按预算组织：

1. 人设与必要行为规则。
2. 用户主动填写的资料。
3. 与本次问题相关且被允许使用的长期记忆。
4. 检索到的角色知识及出处。
5. 最近若干轮对话及早期摘要。
6. 本次文字、用户确认的图片或截图。

不无上限拼接所有历史；本地记忆也不意味着每家云端服务自动共享内部记忆。对话内容和图片发给谁，由当前配置决定。

### 7.3 人物性格

**[确认方向]** 尽量体现雪乃的性格、知识和说话习惯。

**[建议]** 默认人设可恢复；用户可以编辑但不直接覆盖原版。资料注明原作阶段，避免不同时间线的知识混杂。参考台词用于风格理解，不让角色机械复读固定句子。

人设变化会影响后续回答，不倒改历史。角色设定与用户个人记忆分开存储。

### 7.4 知识库

**[建议]**

- 首批支持 UTF-8 TXT/Markdown，后续再扩展 PDF、网页等来源。
- 导入时预览条目、标签、来源和角色时间线。
- 分段、建立索引、查询相关片段，删除文档时同步删除对应索引。
- 初期采用关键词/全文检索打底，后续按效果增加本地嵌入与混合检索。
- 更新资料后重新索引，不需要重新训练整个模型。
- 检索失败或没有资料时，不伪造“原作已经发生”的事实。

### 7.5 微调与训练

**[确认目标]** 可以协助准备数据、训练脚本、评估与推理接入；训练执行依赖实际 GPU 环境。

**[建议路线]**

- 先比较现成指令模型＋人设＋知识库，建立基线。
- 收集/编写多轮情境样本，不只收集单句台词。
- 清洗重复、矛盾、不符合性格及时间线的数据。
- 按场景划分训练/验证/测试，避免相同对话改写跨集泄漏。
- 采用 LoRA/QLoRA 等候选方案，具体框架、基座和许可在选型时验证。
- 评估人设一致性、知识准确性、多轮连贯、通用回答能力和本地延迟。
- 验证合并/转换/量化后的运行效果，不默认所有架构或适配器都能被目标运行时加载。
- 性格微调包和音色训练包是两种资源，社区与软件均需清楚区分。
- 首期普通用户软件不内置一键训练，除非后续确认需要。

## 8. 语音推理与音色包

### 8.1 内嵌运行方式

**[确认]** 使用 GPT-SoVITS 本地语音推理。

**[建议]** 配置匹配的 Python、PyTorch 和依赖组成独立运行组件，主程序负责启动与健康检查。用户不需自行启动 WebUI。官方 API 能用于语音合成与权重切换，具体版本接口须锁定并封装。[S7]

进程只监听本机，优先使用可用端口和应用侧访问保护。桌面前端通过主进程访问，不开放任意本地文件/执行接口。

### 8.2 音色包

每个包包含：

- 名称、作者、描述、封面、版本。
- GPT 与 SoVITS 权重，或明确的公共基础模型依赖。
- 引擎家族与版本、兼容范围、推理配置。
- 参考音频、对应文本和语言标签。
- 可选不同情绪参考音频；不能保证单个音色包天然具备所有情绪。
- 文件大小、校验值、来源及使用说明。

导入先读清单、验证文件与兼容性，再允许试加载；失败显示具体原因。模型文件应作为可信资源处理，避免直接执行陌生包中的脚本；对于可能使用 Python 序列化的权重，优先采用上游支持的受限加载方式，不声称哈希校验能判断文件安全。

### 8.3 生成、播放、口型

- LLM 流式文本先在界面展示。
- 句子/标点分段后进入 TTS 队列，不按每个 token 单独合成。
- 清除用于显示的 Markdown 标记、内部思考、动作标签，不让它们被朗读。
- 保留合理断句，不能误拆小数、缩写、代码内容。
- 为每轮请求、分段和音频分配 ID；异步完成也必须按文本顺序播放。
- 点击停止后取消未开始的合成、丢弃迟到音频、停止当前播放并让人物闭嘴。
- 声音与人物切换不产生重复播放或双窗口同时朗读。
- 第一版基础口型可根据播放音量控制张合；音素级口型需额外对齐方案，不能混为一谈。
- 静音只影响播放；“关闭语音回复”可以阻止新 TTS；“卸载语音模型”释放资源，三者区分。

### 8.4 语音状态

未安装 → 下载中 → 校验中 → 待加载 → 加载中 → 就绪 → 合成中 → 播放中。

异常状态包括缺文件、版本不符、端口冲突、GPU 不可用、显存不足、合成超时、输出设备断开。状态与重试入口在设置中可见。

**[建议]** 首期 API 对话＋本地语音先形成完整体验；全本地模式随后验证并交付，不作为被取消的功能。

## 9. 桌面视觉识别

**[确认]** 支持视觉的 API 可识别桌面；作为独立可开启的模式。

### 9.1 单次模式

- 用户点击“看屏幕”，选择屏幕/窗口/区域。
- 显示待发送截图预览，允许取消、更换来源、缩小范围。
- 确认后截图作为当前消息附件发送给当前支持视觉的模型。
- 不支持视觉时提示换模型，不能默默给文本模型发送无效图片。
- 屏幕解读是回答能力，不包含自动点击、输入或控制桌面的授权。

### 9.2 持续观察模式

**[建议，需验证成本与性能]**

- 明确开始、暂停、停止入口；常驻可见观察指示。
- 本质为限频截图分析，不能宣传为已支持实时视频理解。
- 设置最小截图间隔和每次最多一个待处理观察请求，避免队列无限增长。
- 可选只在画面明显变化或用户提问时发送。
- 主动停止、锁屏、休眠和重启后默认不继续捕获。
- 捕获窗口关闭时提示重新选择，不自动切到全屏。
- 明确是否包含本软件窗口，避免递归截屏与回答自己。
- API 模式会把截图发给该服务商；默认不保存截图到长期记忆。
- 允许用户选择不持久保存截图；退出/取消后清理临时缓存。
- 识别延迟、API 成本和截图频率可见，不能无限自动请求。

## 10. 个人资料与长期记忆

### 10.1 数据分类

| 类型 | 内容 | 默认行为建议 |
|---|---|---|
| 用户资料 | 称呼、主动填写的偏好 | 跨会话使用，可随时编辑 |
| 长期记忆 | 从聊天提取的稳定事实、偏好、事项 | 开关控制，提供来源和删除 |
| 会话记录 | 原始消息与附件信息 | 单独保存，不等同于记忆 |
| 会话摘要 | 为上下文压缩而生成 | 可重新生成，不能覆盖原消息 |
| 角色知识 | 原作设定、角色经历 | 与用户资料分开 |

### 10.2 自动记忆流程

**[建议]** 在完整对话回合结束后异步提取候选记忆，避免每个 token 都触发。来源为用户明确表达，不把角色编造或引用内容直接记为用户事实。

- 记忆条目带时间、来源消息、类别、适用角色与是否固定。
- 新信息与旧信息冲突时，展示更新关系或请求确认，不简单无限堆叠。
- 开关：“自动记忆”“写入前确认”“在当前模型中使用记忆”分开。
- 临时聊天默认不读取长期记忆、不写入长期记忆；是否保存临时记录需明确。
- 手动删除后标记删除/屏蔽，避免下一次后台扫描立刻从旧历史重建。
- API 切换不改变本地记忆，但下一次会按目标模型预算重新选择。
- 记忆写入失败不阻塞当前回复。

### 10.3 查看、导入、导出、清空

- 每条可查看、编辑、删除、固定、追溯来源。
- 导入先预览：新增多少、重复多少、冲突多少；选择合并或替换。
- 导出默认不包含 API 密钥、截图或未选择的聊天全文。
- 清空说明影响：记忆、聊天、摘要各自独立；可选同时清理关联检索索引。
- “删除聊天”不假定“删除记忆”；提供关联记忆处理选项。
- 个人资料是否跨不同角色共用、相处记忆是否按角色隔离：建议前者共用、后者隔离，待确认。

## 11. 设置面板详细清单

**[确认]** 入口在侧边栏右下角。收起后仍能从窄栏或顶部/托盘打开；不让设置入口随着收起永久消失。

**[建议]** 独立浮层面板，左侧分类、右侧内容。小窗口适应尺寸。普通选项即时保存；API 表单、导入与密钥修改用明确保存/测试按钮。运行时不能立即应用的设置标明“下次加载生效”。

### 11.1 常规

| 设置 | 建议默认值/行为 |
|---|---|
| 界面语言 | 中文；多语言后续 |
| 主题 | 跟随系统；浅色、深色可选 |
| 开机启动 | 关闭，由用户主动开启 |
| 启动模式 | 上次模式；持续屏幕观察不自动恢复 |
| 关闭窗口行为 | 首次选择后保存 |
| 减少动态效果 | 尊重系统，可手动调整 |
| 消息字体大小 | 可调，不影响整体窗口缩放设置 |
| 重置界面布局 | 仅重置位置和宽度，不清空数据 |

### 11.2 形象与展示

- 当前形象大预览、资源列表、导入、删除、应用。
- 3D / Live2D / 旧桌宠类型标识与能力说明。
- 服装列表，只显示兼容变体。
- 窗口人物位置：左/右；人物区宽度与显示开关。
- 桌面人物大小、显示器、置顶、锁定位置、鼠标穿透。
- 恢复默认视角、恢复位置、找回人物。
- 眨眼、呼吸、视线跟随、动作幅度等仅在模型支持时显示。
- 换形象不默认换角色记忆、音色或人设。

### 11.3 声音与语音

- 开启语音回复、自动朗读新回复、音量、输出设备。
- 选择音色包、试听固定文本、停止试听。
- 当前加载状态、GPU/CPU 信息、重新加载、卸载释放资源。
- 空闲资源释放策略；自动降级前说明行为。
- 高级：权重路径、参考音频/文本/语言、兼容参数。
- 试听失败显示原因，不改坏当前可用配置。
- 语速仅在引擎支持并验证后开放，不写成所有版本通用。

### 11.4 对话模型

- 本地 / API 模式。
- API 配置增删改、密钥遮挡、测试连接、模型选择。
- 能力展示：文本、视觉、流式等。
- 本地模型导入、文件大小、设备、加载/卸载。
- 高级：温度、最大输出、上下文预算、超时；按适配器能力显示。
- 切模型前若仍在生成，提示先停止或等待完成。
- 不在日志和导出的配置中泄露完整密钥。

### 11.5 角色设定与知识

- 角色名称、身份、性格、表达方式、对用户称呼。
- 预设预览、自定义副本、恢复默认。
- 知识文件导入、来源、索引状态、重建与删除。
- 角色时间线/剧透范围为可选待定项。
- 人设测试对话可独立于正式历史，避免污染长期记忆。

### 11.6 个人资料与记忆

- 称呼与主动填写的资料。
- 自动记忆、写入确认、使用记忆开关。
- 搜索、分类、来源、编辑、固定、删除。
- 导入预览、合并冲突、导出、清空。
- 临时聊天入口与明确的当前状态。

### 11.7 桌面识别

- 默认关闭；选择目标显示器/窗口/区域。
- 单次与持续观察切换。
- 截图预览、发送前确认、频率限制。
- 是否保留附件；默认不保存为长期记忆。
- 当前接收截图的 API 配置与视觉能力状态。
- 立即停止共享按钮始终可用。

### 11.8 聊天与数据

- 数据保存位置、占用空间、备份与恢复。
- 聊天导入/导出、历史搜索、清理附件与音频缓存。
- 数据目录迁移必须先停止写入、备份、验证新路径；失败回退。
- 清空聊天、清空记忆、恢复设置分别提供，不做一个含糊的“全部清理”。
- 数据库迁移前备份，升级失败不覆盖可恢复副本。

### 11.9 快捷键与交互

- 显示主窗口、桌面模式、停止语音、单次看屏幕。
- 冲突检测与禁用，不强占已有系统组合键。
- 人物单击/双击/右键行为，提供恢复默认。
- 鼠标穿透逃生快捷键或托盘操作不可缺失。

### 11.10 组件与关于

- 软件版本、更新说明、检查更新。
- 语言模型、语音引擎、公共基础模型组件列表。
- 安装、修复、校验、卸载；列明文件大小与存储位置。
- 诊断日志导出，默认脱敏。
- 帮助、资源社区、项目主页与第三方组件说明。
- 检查更新失败不影响本地聊天。

## 12. 首次启动、安装与更新

### 12.1 初次引导

**[建议]** 不给新用户塞满假聊天或假记忆。

1. 选择数据目录与基本模式。
2. 配置 API，或选择安装/导入本地模型。
3. 可选启用语音，下载兼容运行组件并导入音色。
4. 选择示例/自有形象；示例资源必须允许随软件分发。
5. 做一条文字与语音测试，展示成功或可操作的失败原因。
6. 引导侧边栏、左右布局和桌面模式；用户可跳过。

首次没有模型时显示配置入口；API 已就绪但语音未就绪时可以先文字聊天。

### 12.2 发布包

**[确认]** 交付 Windows EXE。**[建议]** EXE 安装程序与较大的可选推理组件分开更新。

- 安装包支持选择路径、快捷方式、卸载。
- 语言模型、语音运行时、音色、人物各自版本化。
- 支持手动离线导入组件；完整下载后可以在对应能力范围内离线使用。
- 应用升级默认保留数据和已下载模型。
- 下载有进度、取消、失败重试、校验；可恢复下载视服务器能力实现。
- 不宣称单独一个小 EXE 内含所有模型、训练环境与资源。
- 代码签名证书与是否提供便携版待定；签名、硬件兼容与模型效果分别验证。

### 12.3 运行时服务管理

- 应用持有自己启动的子进程 ID；退出时不结束用户原本运行的其他 Python/模型服务。
- 本地端口冲突选择其他端口或显示可读错误。
- 服务就绪以健康检查和实际小请求为准，不只判断进程存在。
- 崩溃可有限次数重启；禁止无上限重启循环。
- 取消下载、模型加载失败、断电恢复均不留下被误认为完整可用的资源。

## 13. 数据、资源协议与内部接口

### 13.1 主要实体（建议）

| 实体 | 主要字段 |
|---|---|
| Character | id、名称、人设版本、知识空间、默认资源引用 |
| AvatarPackage | id、版本、类型、入口、动作/表情/服装清单、能力、校验值 |
| VoicePackage | id、版本、引擎版本、权重、依赖、参考音频、语言 |
| ModelProfile | id、模式、提供商、模型、地址、密钥引用、能力、参数 |
| Conversation | id、角色、标题、创建/更新时间、临时模式 |
| Message | id、会话、角色、文本、状态、使用的模型、附件引用 |
| Memory | id、内容、范围、来源、更新时间、固定/删除状态 |
| KnowledgeDocument | id、来源、角色、版本、索引状态 |
| LayoutPreferences | 侧栏状态、人物左右、列宽、各模式窗口位置 |
| ComponentInstallation | id、版本、设备变体、路径、校验状态 |

主进程管理持久状态，多个窗口订阅同一个会话状态；不能各窗口各自启动一份相同语音任务。

### 13.2 资源导入协议

- 统一清单 schema_version，区分 avatar、voice、motion、persona、knowledge。
- 包内相对路径必须规范化，不允许解压写出目标目录。
- 校验依赖、版本、大小与入口；不支持的资源不会直接执行。
- 本地导入产生预览页：名称、来源、兼容能力、占用空间、缺失依赖。
- 先安装新资源、试加载成功，再切换当前引用。
- 删除使用中的资源先要求切换或停用，避免悬空引用。
- 同 ID 不同版本允许覆盖确认或并存，具体策略统一。

### 13.3 请求生命周期

一次回复带唯一 generation_id；停止、重生成或切换策略会使旧 ID 失效。LLM 文本、TTS 片段、人物动作与截图请求都绑定此 ID。迟到事件检查 ID 后丢弃，避免停止后仍然说话或旧回复混入新对话。

### 13.4 进程与前端边界

- 渲染器不开任意 Node 执行能力，通过窄化 preload/IPC 调用。
- IPC 参数校验；API 密钥不通过 UI 状态广播。
- 本地服务不对公网开放。
- 日志记录状态、时长与错误码，默认不记录完整私密对话、截图或密钥。
- 社区内容和模型输出按不可信输入展示，不运行其中 HTML/脚本。
- 第三方资源安装与程序更新是两条流程，资源包不能伪装应用更新。

**[建议]** 第一阶段采用“资源目录站＋GitHub Discussions”；第二阶段若确实需要站内账号、私信、即时发布，再增加独立后端。不要为了外链分享一开始就承担完整网盘系统。

### 14.3 资源分类

### 14.4 投稿字段与发布流程

投稿至少包含：

1. 标题、类型、描述、作者。
2. 资源版本、支持的软件与引擎版本。
3. 封面、可选截图或音频试听。
4. 文件大小、下载地址、提取码、可选校验值。
5. 安装步骤、依赖和已知限制。
6. 来源和允许的使用/分享范围。
7. 可选公开联系方式，明确“其他访客可见”。
8. 更新说明。

**[建议首期]** 页面引导用户到 Discussions 指定分类投稿；管理员按模板检查后，将元信息纳入资源目录。目录可以由已审核数据构建，网站显示最近更新时间。未审核帖子仍可在讨论区存在，但不自动成为“推荐可安装资源”。

Actions 的写权限只存在于受控构建流程，不能把仓库写入令牌放到 Pages 前端。构建系统不执行投稿者提供的代码，也不自动下载并运行权重。

### 14.5 下载与联系方式

- 外链按钮明确展示网盘/外部来源；新标签打开。
- 提取码可以复制；无提取码时不显示空按钮。
- 链接失效可报告；管理员标记失效、更新或下架。
- 只提供联系方式的资源明确标为“联系作者获取”，不能伪装为可直接下载。
- “私下联系”默认指社区之外的联系方式，不等于已实现站内私信。
- 发布者可以编辑或移除自己的联系方式。
- 首期建议用户下载后从 EXE 手动导入；后续再增加自定义协议一键导入。
- 一键导入必须预览并确认，不在打开网页时自动执行或加载资源。

| 功能 | 轻量首期 | 独立社区后端阶段 |
|---|---|---|
| 发帖与评论 | GitHub Discussions | 网站原生 |
| 身份 | GitHub 账号 | 可选邮箱或第三方登录 |

| 通知 | GitHub 自身通知 | 站内通知 |

本地浏览器收藏不等于跨设备同步；静态资源索引不等于实时展示所有新帖子。

### 14.7 管理与内容生命周期

**[建议]** 管理员可以审核、标记版本不兼容、隐藏违规/恶意链接、处理举报。保留发布状态和更改记录。

建议状态：草稿/投稿 → 待审核 → 已收录 → 更新待审核 → 失效/下架。静态首期通过 GitHub 的管理动作实现，不虚构已经存在的后台。

不要未经用户操作把本机记忆、截图、聊天或 API 配置发布到社区。资源分享是用户主动导出和投稿，不是软件后台自动上传。

### 14.8 大文件与费用边界

GitHub Releases 可作为部分资源的分发渠道，单文件小于 2 GiB；是否适合具体资源还要考虑依赖、版本与访问体验。[S6] GitHub Pages 用于静态网站，不能直接充当任意用户写入的文件服务器。[S5]

首期大型资源可以全部采用外链；社区本身并不因没有自建大文件存储而无法成立。独立后端、对象存储和域名是否付费，以及预算上限均待确认。

## 15. 异常、性能与质量

### 15.1 主要异常

| 场景 | 应有行为 |
|---|---|
| API 密钥无效 | 明确指出当前配置失败，保留提问，提供打开配置 |
| API 不支持图片 | 发送前阻止并提供切换模型，不丢失文字与截图预览 |
| 网络中断 | 保留已生成文本，重试不重复写消息 |
| 本地模型显存不足 | 显示可选较小模型/减少上下文/调整设备，不擅自上传云端 |
| 语音组件缺失 | 继续文字聊天，提供安装入口 |
| 语音合成失败 | 文字保留，取消该段或重试，不让后续音频顺序错乱 |
| 人物加载失败 | 保留旧形象或进入文字模式，显示可修复原因 |
| 侧边栏快速重复切换 | 最终布局符合最后一次操作，不堆叠错位动画 |
| 多屏断开 | 窗口/人物返回可用屏幕 |
| 资源下载中断 | 不标记为已安装；可重新下载/恢复 |
| 社区不可用 | EXE 本地功能不受影响 |
| 数据升级失败 | 回退到备份并说明，不静默清空 |

### 15.2 性能目标（建议，尚未实测）

- UI 不因模型加载、合成或数据库批量操作长时间阻塞。
- 人物目标 30 FPS，条件允许可选 60 FPS；后台/低性能模式降低帧率。
- 同一时刻只有一个人物视图活跃渲染作为默认，避免双份 GPU 占用。
- 模型加载耗时与首字、首段语音延迟分开测量。
- LLM、TTS、人物渲染联合测显存，不只测单模块。
- 不承诺指定机器实时运行大模型；首次测试记录 CPU、GPU、显存、内存、模型大小与上下文长度。
- 停止播放需及时响应，目标在本地约 200ms 内；实际效果通过测试验证。
- 无网络且组件齐全时，完整本地文字/语音/人物流程应可用；云端 API 和社区自然不可用。

### 15.3 验证方法

- 单元测试：队列顺序、取消与迟到事件、记忆去重、资源兼容、布局状态转换。
- UI 测试：侧栏/人物左右切换、输入法发送、设置持久化、导入失败恢复。
- Windows 实机：透明窗口、穿透、托盘、DPI、多屏、睡眠、安装卸载。
- 集成测试：真实 API、小型本地模型、真实 GPT-SoVITS 音色的完整一轮对话。
- 人物视觉评审：正面/侧面、转头、嘴型、穿模、换装与动作过渡。
- 社区测试：外链、投稿指引、搜索、失效资源、无登录浏览、构建数据校验。
- 模拟服务可用于开发，不作为“真实推理已完成”的验收证据。

## 17. 验收清单

下面均为拟定验收项，不是完成记录。

### 17.1 UI 与窗口

- [ ] 不存在与内容明显异色的传统软件名标题栏。
- [ ] 侧边栏展开时不覆盖正常宽度下的主内容。
- [ ] 人物靠左，收起侧栏后自动靠齐新内容左边界，无遗留空白。
- [ ] 人物靠右，侧栏变化后保持右侧，聊天使用释放的空间。
- [ ] 切换左右布局不丢失草稿、消息或滚动位置。
- [ ] 缩放窗口、最大化和不同 DPI 下输入框始终可用。
- [ ] 设置入口在侧栏展开/收起、桌面模式下都有可达路径。
- [ ] 进入桌面模式后主窗口隐藏，人物保留，不重复发声。
- [ ] 鼠标穿透后能从托盘或快捷键恢复。
- [ ] 断开显示器后能找回人物。

### 17.2 对话、模型和记忆

- [ ] API 配置可增删改、测试并保存，密钥不出现在导出文件中。
- [ ] 本地模型能够完成真实回复，退出后不残留本软件进程。
- [ ] 切换 API 后仍可使用同一份允许使用的本地记忆。
- [ ] 记忆可查看、编辑、删除、导入、导出。
- [ ] 临时聊天不会意外写入长期记忆。
- [ ] 清空记忆不会被后台从旧聊天立即恢复。
- [ ] 失败与停止的回答不被当成完整事实自动记忆。

### 17.3 语音与人物

- [ ] 导入兼容音色后可以试听与朗读回复。
- [ ] 不兼容音色给出可理解的错误，不破坏当前音色。
- [ ] 分段音频按文本顺序播放。
- [ ] 停止后迟到音频不继续播放，人物嘴部及时闭合。
- [ ] 形象/服装切换保留角色记忆和会话。
- [ ] 3D 与 Live2D 共用上层对话流程，不要求重写聊天模块。
- [ ] 未适配的旧桌宠格式不会被宣传为已支持。

### 17.4 屏幕与社区

- [ ] 不支持视觉的模型无法误发截图。
- [ ] 截图范围、当前发送目标与观察状态清晰可见。
- [ ] 重启不自动恢复持续屏幕共享。
- [ ] 只识别画面，不擅自控制桌面。
- [ ] 社区可以独立访问，EXE 不依赖社区在线。
- [ ] 网盘链接、提取码、联系方式与资源依赖展示明确。
- [ ] 投稿审核方式与是否实时发布符合所选社区方案。
- [ ] 网站静态前端不包含仓库写权限或服务端管理密钥。

### 18.2 本文明确没有默认加入的功能

- 自动操作用户电脑、自动点击或发送消息。
- 自动上传私人聊天、记忆与桌面截图到公共社区。
- 软件内训练所有模型或随安装包附带巨大训练环境。
- 任意 3D 服装无条件互换、任意旧 EXE 无修改内嵌。
- 自动收费、会员订阅、支付系统或资源交易。
- 移动端、macOS、Linux 全平台同时首发。
- 未经验证的实时视频理解、音素级口型或多人物同时聊天。

这些可以后续讨论；未加入不代表技术上永久不能做。
