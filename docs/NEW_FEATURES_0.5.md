# 下一阶段：形象、陪伴机制、下载与社区

记录日期：2026-10-26。对应本轮确认的三个想法与社区开发任务。

本文是产品需求与实现约定。已经有的桌面窗口、API、本地模型服务、桌宠与下载管理属于现有基础；本轮新增的场景、衣装、情绪与赞助能力必须按实际代码和验收记录标记，不能因为出现设置项就宣称完整实现。真实 3D 模型、表情、骨骼与动作素材仍由后续资源接入。

## 1. 换装不是瞬间替换，而是一次登场

### 1.1 用户看到的流程

1. 人物展示框靠侧边提供“衣装”按钮；展开为框内侧边面板，不遮挡聊天输入框。主侧栏的展开与收起不改变该面板的归属。
2. 面板显示衣装预览、名称、资源状态、当前选中状态及解锁条件。未下载、未解锁、加载中、可用和资源错误分别显示。
3. 用户选择一套可用衣装，先在后台检查并预加载目标形象。目标资源未准备好时，原人物继续可见，可以取消。
4. 预加载成功后，当前人物向左走出展示框。原角色的离场动作结束后，目标形象从右侧进入，停到原本的人物站位，面向用户完成一次简短招呼。
5. 衣装选中状态在进入完成后才提交。打招呼仅播放一次；音色未配置或静音时只显示气泡，不能因此阻止换装。
6. 切换失败时回到原衣装与站位，保留对话和音色设置，并显示可重试提示。

左右是展示框的局部坐标，不随主界面人物放左或放右而颠倒。可以以后增加反向登场，但首版使用统一的“左出、右入”规则。

### 1.2 动作与切换约定

- 状态机：`idle → preloading → exiting → entering → greeting → idle`；错误返回 `idle`，并保留此前已完成的衣装。
- 每次切换都有请求编号。连续点击只保留最后一次选择；旧加载、旧招呼和旧动画的迟到完成事件不能覆盖新选择。
- 任一时刻最多显示一个“当前已提交”形象；过渡时允许两个渲染对象，但不会同时接受交互或同时朗读。
- 走动是动画片段与模型根节点位移共同完成，不把静止模型简单横向拖拽冒充走路。资源没有行走动作时，使用明确的淡出/淡入退化方案。
- 衣装若共用骨骼，可换网格或材质；若骨骼、比例或渲染器不同，则走统一形象适配器，不能强行复用不兼容动作。
- 模型销毁、窗口关闭、用户取消和新切换请求都可以清理旧计时器、动画监听、临时模型与声音请求。
- 开启“减少动态效果”时使用短淡入淡出，不播放左右穿场；“直接换装”可作为单独偏好。
- 未正式接入模型时只展示资源与接口状态，不能展示虚假的“换装成功”。

### 1.3 资源与接口

建议衣装清单包含 `id`、名称、预览、渲染器类型、版本、资源 URL/大小/SHA-256、兼容骨骼、默认站位、可用动作、许可说明与解锁规则。

渲染适配器至少提供 `preloadOutfit`、`enter`、`exit`、`setOutfit`、`setGaze`、`setLighting`、`setEmotion` 与 `dispose`。3D 和 Live2D 的差异在适配器内处理，上层聊天、衣装面板、情绪和环境设置不依赖某个具体模型库。

## 2. 眼神与头部跟随

### 2.1 范围与表现

- 只在鼠标位于当前应用的人物展示框或指定交互窗口内时跟随；首版不采集全桌面鼠标轨迹。
- 将鼠标位置换算到人物框的局部坐标 `[-1, 1]`，结合眼部和头部实际骨骼限制计算方向。
- 眼睛先响应，头部稍慢；都采用平滑插值和角度上限，避免瞬间折头、斜眼或模型穿帮。
- 鼠标离开、窗口失焦或形象隐藏后，缓慢回到自然朝向；拖动人物、菜单打开、换装或指定动作期间可暂停跟随。
- 跟随和眨眼独立：注视不能覆盖眼睑闭合，眨眼不能重置头部朝向。
- 眼球骨骼、眼神参数或头部骨骼缺失时，只启用资源真正支持的部分。不能移动整个人物假装眼睛已跟随。
- 设置提供总开关、头部跟随开关、强度与恢复速度；“减少动态效果”降低位移或停用。

### 2.2 验收情景

鼠标在四角、快速掠过、离开窗口、跨显示器、改变人物大小、收起侧栏、切换左右位置及拖拽过程中均不得出现角度越界。坐标始终按新的展示框测量；只在动画帧中更新，不因频繁鼠标事件重复渲染整页。

## 3. 环境与以人物为中心的背景扩散

### 3.1 环境预设

| 环境 | 视觉方向 | 模型灯光目标 |
| --- | --- | --- |
| 森林 | 柔和绿色、较低对比、树影层次 | 柔和天空环境光、暖色主光、较弱补光 |
| 海边 | 浅蓝天空、沙色地面、清爽空气感 | 较明亮的日光与天空补光，限制高光过曝 |
| 城市 | 中性灰蓝、明确的空间层次 | 中性环境光、可辨识主光，后续可扩展夜景灯 |

这些是美术参数方向，不是已经配好的 HDRI 或照片素材。正式环境资源应记录来源、许可、分辨率和 SHA-256。高分辨率天空盒等大文件通过统一资源管理安装。

### 3.2 展示框和全 UI 两种范围

- 默认只改变人物展示框里的环境和对应模型光照。
- “应用为整个界面背景”打开后，聊天区域与侧栏使用同一环境的弱化背景层；文字面板保留足够遮罩和对比度。
- 扩散起点使用当前人物在应用窗口中的实际中心点，不能写死在屏幕正中。人物左置、右置、拖拽、改宽与收起侧栏后起点都会更新。
- 切换时，新背景在旧背景上按圆形遮罩向外扩展；半径达到距离起点最远的窗口角，保证覆盖整个 UI。
- 原背景保留到新背景加载成功、扩散完成后再释放；资源失败时原背景继续显示。
- 用户快速切换环境只让最后一次选择完成；关闭全界面背景时使用对应的回退过渡。
- “减少动态效果”使用短淡化或直接切换。窗口处于后台时不持续播放装饰性动画。
- 自定义背景、主题色与场景存在优先关系：全界面场景关闭时恢复用户原背景，不覆盖原设置。场景开启时主题强调色仍可自定义。

### 3.3 渲染接口

环境配置分别提供 `background`、`lighting`、`exposure`、`toneMapping` 与可选天空盒。UI 的背景色和模型灯光来自同一份环境 ID；没有真实渲染器时可以先展示背景与参数状态，但需说明模型灯光仍待接入。

## 4. 情绪、好感度、体力与衣装解锁

### 4.1 用户提出的方向

保留以下原始想法，不在实现时遗漏：情绪系统与好感度系统；签到或赞助解锁更多皮肤；连续对话多轮、负面对话内容可以影响好感度和体力。

本轮已接入 `src/companion/relationship.mjs` 的本地状态与界面：成功完成一轮对话才计入体力消耗，连续前 5 轮每轮减 2，之后每轮减 4；按经过时间每分钟恢复 2，超过 15 分钟未对话后重新计算连续轮数。每日签到好感度加 2，累计 3 / 7 / 14 天产生衣装资格标记，但没有因此提供尚未接入的真实皮肤。界面可显示平静、愉快、疲倦或需要空间的状态。代码提供显式 `boundary` 事件（好感度减 2、体力减 4），但尚未接入自动内容分类，不会扫描普通负面文本或因用户表达难过自动扣好感。赞助验证未启用。下文其余内容是继续完善的设计与验收目标；负面内容判定、付费权益和扩展奖励策略仍需单独确认。

### 4.2 三个维度分别负责什么

| 维度 | 含义 | 影响范围 |
| --- | --- | --- |
| 情绪 | 当前互动中的短期状态，例如平静、愉快、专注、困惑、疲倦 | 表情、语气、短动作；随时间和新情景恢复 |
| 好感度 | 长期相处记录，不等于是否答应任何要求 | 自然称呼、互动内容与可选衣装解锁；不能改写核心人格 |
| 体力 | 当前互动节奏和连续陪伴负荷 | 疲倦动作、休息提示与自动动作频率；不能强制用户付款才能继续基本聊天 |

建议将长时间连续对话首先作用于体力，而不是把正常陪伴自动视为好感下降。用户表达难过、自责、压力或谈论负面经历不等于冒犯角色；建议这些情况不扣好感。若要引入边界反馈，应针对明确侮辱、反复恶意挑衅或强迫角色的行为，且允许用户关闭机制。

### 4.3 计算与可靠性

- 所有数值有上限、下限、每轮变化上限和短时间重复事件去重。网络重试、流式分片、补译与重新朗读不得重复记一次对话。
- 用户发出消息不立即扣体力；至少成功产生一轮回复后再记录，取消、报错与超时不扣分。
- 情绪识别不能仅凭某个关键词认定“负面”。规则优先给出可解释原因；模型分析失败时不改变长期数值。
- 休息按经过时间恢复体力，退出应用不会持续扣体力；恢复有上限，系统时间倒退不能刷取奖励或造成负分。
- 好感度不因漏签到、长时间没有打开应用、换 API 或更换设备而惩罚下降。
- 本地保存包含 schema 版本、事件 ID、更新时间与来源；可以导出、重置或关闭数值显示。历史聊天不自动补扣。
- 对话提示只获得必要的状态摘要，不把“得分多少”机械插入每句话，也不把成长阶段拆成不同人格。

### 4.4 签到

- 每个本地自然日最多领取一次；时区明确，跨日与夏令时按日期处理。连续天数和累计天数分开记录。
- 首版可采用累计签到解锁衣装。断签不撤销已解锁资源；连续签到奖励可以有补签或宽限策略，但具体数值待确认。
- 解锁只改变使用权限，不自动开始大文件下载。衣装下载前仍显示大小、来源和确认入口。
- 本地签到只是休闲机制，不作为防作弊的付费权益账本。

### 4.5 赞助

- 赞助提供的衣装、金额、说明与作者权限必须单独确认。当前不添加收款码、不生成虚假订单、不假装已有支付回调。
- 若以后实现真实赞助解锁，使用服务端签名权益或明确的人工兑换流程；不能仅以本地布尔值判断付款。
- 基础聊天、导入用户自己的模型、已有衣装和用户数据不应因停止赞助而失效。
- 赞助与好感度分离：付款不购买角色的情感，也不提高聊天中的顺从程度。

## 5. 独立资源下载与备用来源

### 5.1 安装与首次启动

基础 Setup 内只放应用、UI、小型桌宠形象素材、角色说明和必要下载工具。安装期间不下载模型、音色或 Python 环境。第一次打开软件后，资源向导列出本地对话、翻译、语音与桌宠语音；可跳过，先使用 API 文字聊天。

本地对话、翻译与语音共享运行环境，但模型分别安装、分别显示状态。仅准备桌宠预录语音无需 Python。用户已有的自定义模型与环境配置不能被默认资源自动覆盖。

### 5.2 每项大文件单独发布

- 本地 NLP/GGUF、翻译 GGUF、GPT 权重、SoVITS 权重、BERT/HuBERT 权重与运行环境包各自对应固定 GitHub Release 资源链接。
- 清单记录每个文件的路径、长度、SHA-256、主源、备用源、许可证和版本。运行环境可能分卷，但每卷都可单独校验与续传。
- 不从网页里临时抓取“最新模型”替换固定版本；链接改变只能通过清单更新。
- GitHub 大文件镜像上传前先校验原文件，上传后再次核对发布资产的长度和摘要。每个源必须提供同一份字节内容，不能悄悄换精度或版本。
- 允许原作者的固定 Hugging Face 下载地址作为校验相同的备用源。没有真实可用镜像时明确显示，不填虚构的加速域名。

### 5.3 aria2 与失败恢复

内置 aria2 下载引擎，不要求用户另装 Motrix。采用多连接、断点续传和校验；不开放 RPC 服务。多连接速度受源站限速、网络、磁盘和连接数影响，不承诺固定倍率加速。

资源卡保留真实进度、已下载/总大小、正在使用的来源，以及下载、重试、取消与“无法下载，寻求帮助”入口。超时或源不可用后尝试清单中的其他已校验来源；取消是用户意图，不自动重新启动备用源。

aria2 的稀疏分块文件和普通 HTTPS 的连续下载文件必须分开存放。未校验完整的文件不得被模型服务使用。取消和程序重启后可以复用临时数据；校验失败时清理坏块或重新下载，不跳过校验来宣布成功。

### 5.4 帮助入口

统一跳转 `https://fqxxzyw.github.io/Yukino-Companion/#help/download`。帮助页覆盖网络与代理、备用源、手动下载与 SHA-256、环境与模型区别、磁盘空间、CPU/GPU、路径选择和反馈方式。反馈中不自动附带密钥、聊天正文或个人记忆。

## 6. 以 GitHub 为后端的社区网页

### 6.1 首版范围

- 独立于 EXE 的网页，浅蓝/白色、清晰正文、简约导航，适配手机与桌面。
- 同人文章/网文二创、音色资源、建议、Bug 四类内容；列表、分类、搜索、详情、公开评论与作者 GitHub 身份。
- 真实数据来自指定仓库的 GitHub Issues；不使用假用户、假作品、假点赞或仅写在浏览器本地的“成功发布”。
- 投稿使用 GitHub 表单完成身份登录与最终确认。网页必须明确写“前往 GitHub 登录并发布”，而不是声称网页已经持有登录会话。
- GitHub 提交后可以返回网页刷新；作者在 GitHub 编辑或删除后，页面重新读取真实状态。
- 大型模型只保存下载链接、大小、SHA-256、版本、参考音频要求、训练/素材来源及使用许可；不往 Issue 正文塞二进制模型。
- 公开投稿不能存 API Key、个人聊天和用户私密记忆。本站不会要求访客提交 API Key 才能看文或下载资源。

### 6.2 登录能力的准确边界

GitHub Pages 负责静态网页，GitHub Issues 负责身份、内容与讨论，这是可运行的无自建数据库方案。站内无跳转编辑、登录头像会话和代用户发帖需要再配置 GitHub OAuth/GitHub App 与安全服务端；不能在公开 JS 中写客户端密钥，也不能把维护者令牌发给访客。

首版交付以“真实 GitHub 登录后投稿并回到网页展示”为准。若以后要求完全站内登录，需补齐应用注册、回调域名、权限范围、CSRF/PKCE、服务器端令牌管理、退出和撤销授权；不能把空按钮标成完成。

### 6.3 内容与资源分享

- 文章：标题、简介、正文、标签、作品来源/原创声明与可选外链。
- 音色：名称、适配的 GPT-SoVITS 版本、GPT/SoVITS 对应文件、参考音频要求、下载地址、大小、SHA-256、训练数据来源与许可、说明。
- 反馈：应用版本、系统/设备概况、复现步骤、期望与实际结果、经过脱敏的错误片段。
- 帮助文档：首次安装、完整性检查、API 获取与接入、下载失败、语音链路、CPU/GPU、社区投稿。
- 普通用户只操作自己的投稿，管理员按 GitHub 仓库权限处理内容。网页只渲染允许的 Markdown，不执行用户 HTML 或脚本。

### 6.4 帮助文档的小广告

广告正文、展示位置、联系方式或链接最后由用户确认。当前帮助正文不插入广告，也不凭其他对话里的个人资料自行生成宣传内容。后续建议放在帮助页末尾单独的小卡片，保持清晰标注和低干扰，不伪装成故障处理必需步骤。

## 7. 验收清单

1. 新电脑安装基础 Setup 时断网仍能完成程序安装；进入应用后由用户选择资源再下载。
2. 只用 API 可以跳过全部本地资源；只选桌宠语音不会安装 Python。
3. 每个大文件显示自己的大小和下载进度；主源失败会走真实备用源；取消后不暗中继续下载。
4. 下载后校验失败不启用模型；重启后可以继续未完成的下载；用户自定义文件保持不变。
5. 新安装器中文正文可读，欢迎、目录、进度与完成页布局不依赖旧版侧图。
6. 社区空数据时显示真实空态；GitHub 请求失败有重试；投稿确实进入 GitHub，返回后可以看到公开内容。
7. 帮助页包含可复制的 SHA-256 检查命令、官方 API 文档链接及不泄露密钥的反馈指引。
8. 对模型素材未齐备的能力显示待接入，不把静态图、占位动作或仅有设置项算作正式 3D 完成。
9. 衣装切换、视线、场景扩散的适配器具备取消、窗口关闭和减少动态效果路径；真正模型接入后再做视觉验收。
