更新：2026-10-31。本页记录**第一阶段下载任务逻辑修复**；下文“本轮”均指该阶段，当时没有启动应用、Vite、Electron、推理服务或真实模型下载。后续的安装位置隔离、语音缓存、句子批处理、API 表单及真实验证进度见 [语音与安装作用域](SPEECH_AND_INSTALL_SCOPE.md)。场景开发继续暂停，等待用户提供新的 HTML / JS。

## 已复现的问题

`tests/download-entrypoints.test.cjs` 执行真实 `main.cjs` IPC 处理函数、真实 `TranslationService` 和原下载器。Electron、推理进程与网络仅在边界替换；权重是临时目录内的固定摘要小文件，不是可推理模型。

修正前四项全部失败，日志 `.local-dev/download-entrypoints-before-20261031.log`：

1. 翻译设置的“取消下载”调用 `translation-cancel`，主进程却只执行 `cancelRequests()`；权重安装 token 未取消，下载仍完成并保存配置。
2. 设置页正在准备翻译权重时，部署向导的相同请求被判“正在准备”；向导把忙状态当失败并调用全局取消，导致原下载也中止。
3. 取消向导会取消由设置页发起的翻译安装，而不是仅取消向导自己的等待。
4. 没有运行中的向导时，调用向导取消仍会全局取消其他入口的下载。

## 本轮修正

### 进程内在途任务与取消所有权

- 新增 `electron/resource-jobs.cjs`，在首个异步预检前预占任务。同 key 的调用者加入同一底层操作，不再次发起下载或校验；各调用者持有独立订阅和可选 AbortSignal。
- 有其他订阅者时，取消某一调用者只释放该订阅，不中止共享工作。最后一个订阅者取消才中止底层 controller，并等待文件句柄、worker 和清理结束。
- 资源页明确取消 / 应用退出仍可以停止该资源实例的所有相关任务。向导取消不再调用各服务的全局取消。
- 取消后立即重试，重试先登记为可取消的排队任务，等待旧操作退出后才开始写入；再次取消也能找到这个重试。旧 finally 不能解除新任务的锁，取消排队重试也不能丢失原写入的退场锁。已取消操作即使晚返回成功，也不会向调用者返回成功。
- 不同 key 写同一目标时按已存在任务顺序等待，再由原摘要校验复用完整结果；不重叠目标继续并行。取消尚未开始的排队任务会立即释放其未使用目标，不等待其他所有者的下载结束。

### 接入范围

| 服务 | 在途身份 / 冲突处理 | 保留机制 |
| --- | --- | --- |
| 翻译 | 同一服务实例的一次权重安装，覆盖 manifest 读取、已有文件校验和下载全过程 | 原固定清单、大小 / SHA-256 校验、已验证 bundled / custom 权重复用、取消 token 与晚回调保护 |
| 语音 | pack + 可选 GPT / SoVITS component；归档和解压目标路径共同参与冲突等待 | 原独立组件安装、core / voice 并行、SHA-1 Git 配置与 SHA-256 权重校验、受控解压 |
| 本地角色 / 桌宠资源包 | resource id + 归档 SHA-256 | 原 staged 安装、内部清单 / GGUF 校验、未知目录不覆盖、旧资源保留 |
| 公共运行环境 | 请求 variant；同一 runtime 根目录的不同 variant 串行 | 原自动硬件选择、完整归档校验、随机 staging、独立 probe、原子 current.json 和旧可用环境保护 |

这些注册表属于应用主进程中的服务实例；不是跨应用进程、构建脚本或安装器的统一注册表。清单来自固定应用资源，本轮不支持在任务运行中热换清单。

### 主进程与向导

- `main.cjs`：翻译设置取消连接到真实 `cancel()`；携带 requestId 的单次翻译取消仍不会取消独立安装。聊天 Stop 保持 `cancelRequests()`，不误停后台权重。
- 向导的 runtime、translation、voice core、默认 voice pack 和资源包安装均传递本次向导的 signal。
- 一个功能失败不再中止其他独立功能；仍等待各任务结束并进行最终磁盘检查，不把回调成功当作全部资源已就绪。
- 不依赖 React 设置页或向导是否挂载来维持任务，也不以禁用单一按钮代替主进程去重。
- 保留自定义权重、参考音频、配置的原提交保护；不更改资源目录或正式用户数据。

## 恢复能力与未完成边界

本轮复用现有磁盘缓存及续传器，没有重写下载协议：完整文件先验摘要；HTTPS 连续 partial 与 aria2 稀疏 partial 分开；分卷重新验证后复用；原 Range / Content-Range 和整体摘要检查保持。相关既有回归继续执行。

**这还不是完整持久化下载中心，也不表示下载相关全部需求已完成：**

- 注册表只保存进程内在途操作，没有新增持久 taskId、`jobs.v1.json`、重启恢复队列或统一下载中心。
- “重新安装时利用已验证文件 / partial”不等于用户可操作的暂停 / 恢复状态机；未新增暂停按钮或清理缓存入口。
- 未新增 ETag / If-Range 绑定、进度 revision / 节流机制或网络失败自动重试策略；不能凭 Range 单测宣称全部服务端续传场景已验证。
- 仍需验证真实 Windows 下载、托盘 / 退出 / 重启、网络断开、磁盘不足和实际缓存恢复；本轮没有启动真实应用验证这些路径。
- 未运行安装器或构建脚本的下载链路，不宣称它们共享上述注册表。
- 未做真实语音、LLM、GPU、音色听感测试；小文件、模拟 probe 与 IPC harness 不能证明真实模型可运行。
