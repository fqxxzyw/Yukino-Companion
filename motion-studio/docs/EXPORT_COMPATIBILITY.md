# 导出与格式兼容性

| 结果 | 扩展名 | 用途 |
| --- | --- | --- |
| 工程文件 | `.motionproject.json` | 在编辑器继续修改时间线、轨道和关键帧。仍可打开旧版 `.yukinomotion`。 |
| 运行时动作包 | `.motion.json` | 交给独立播放器或同版本求值库。包含实际关键帧、模块、片段时间与混合参数、模型映射和资源引用。 |
| 带动画的三维角色 | `.glb` | 对 GLB 或 glTF 角色导出绑定模型和一段烘焙后的标准 glTF 2.0 动画，可在工作台重新导入。 |
| VRM 角色 | `.vrm` + `.motion.json` | 可导入 VRM 0.x、VRM 1.0。保留原始 VRM 并单独导出动作 JSON；VRM 工程禁用带动画的 GLB 导出。 |
| 其他三维格式 | glTF、VRMA、FBX | 可导入未压缩的 glTF 2.0 模型。当前无 VRMA 或 FBX 导入导出。 |

动作包保存可重复求值的运动学数据。骨骼位移、四元数旋转、表情权重、轨道遮罩和程序化模块的参数可由配套运行时恢复。模型、材质和贴图仍来自本地原文件。打开自定义 VRM、GLB 或 glTF 的动作包时，需要选回对应的模型及依赖。专属模块依赖源角色资源与适配；同一模型上的验证结果无法直接覆盖其他角色。

原生动画导入阶段会将可用轨道转换为模块。动画缩放、三次样条、独立网格的同名形态权重可能在转换中省略，相关限制显示于模型能力。本地交付和服 GLB 的走路与问候以形态权重保留烘焙裙摆，可以随原模型在播放器回放或烘焙到 GLB。VRM 的弹簧配置保留在原模型中，预览时根据模型运行，动作包不记录模拟结果。音频及音素同步不在当前动作包范围内。

GLB 导出重新读取绑定的本地模型，按工程帧率采样，写入实际节点的局部旋转、局部位移和网格形态权重。导出时保留模型的蒙皮、几何和贴图，烘焙结果使用标准动画通道。工程片段、混合参数和可编辑关键帧继续由 `.motionproject.json` 保存。采样点之间采用标准线性或四元数球面插值。具体逐帧验证见 [测试报告](TEST_REPORT.md)。
