# 模型适配指南

## 加载条件

工作台接受 VRM 0.x、VRM 1.0，以及未压缩的 GLB 2.0 和 glTF 2.0。VRM 请选原始二进制 `.vrm`，GLB 需将缓冲区和贴图内嵌。glTF 可以使用同批选入的本地 `.bin` 和贴图，也可选中依赖所在的目录来保留文件层级。加载器用这些本地文件解析资源。它会指出缺失依赖、不能识别的版本、需要额外解码的压缩模型、不支持的必需扩展和多组蒙皮权重。01 白色两件泳装使用八权重蒙皮，保留在审计清单中。内置泳装选项使用已登记的 03 连体款。

内置资源校验登记的字节数和 SHA-256。自定义 VRM、GLB 和自包含 glTF 使用文件 SHA-256。含外置资源的 glTF 对原始 glTF、引用相对路径和对应依赖的指纹一起计算组合 SHA-256。已绑定骨架的模型载入后会识别骨骼及表情，并显示实际可控关节数量。纯静态网格需要先添加蒙皮骨架或形态键才能载入工作台。

## 语义 ID 与参考姿态

`ModelRig` 分别收集实际骨骼和形态键，通过名称别名建议映射。例如 `J_Bip_C_Head` 对应 `head`，`J_Bip_R_LowerArm` 对应 `rightLowerArm`，`MouthSmile` 对应 `smile`。VRM 优先读取模型声明的人体骨骼与正式表情。未识别的骨骼、形态键或正式 VRM 表情以 `native:bone:`、`native:morph:` 或 `native:vrm:` 为前缀保存为原始模型通道。VRM 已经绑定到正式表情的形态目标不会再作为独立滑杆重复列出，仍可操作其他有实际变形的原始形态键。共享名称的原始形态会应用到多个实际网格，例如校服主体和轮廓。

若模型有 `Idle_Breathe`，适配器以其第零秒姿态为编辑参考。其他模型以加载姿态为参考。视窗「参考姿态」按钮显示文件初始姿势，用于与编辑结果对比。语义旋转在场景参考坐标下记录，应用时由关节自己的参考方向转换到骨骼局部轴。位移记录为模型参考高度的比例，应用时转换到父节点局部坐标。该策略用于保持同一动作在不同参考姿态上的方向一致；复杂姿态、接地和衣物需要逐模型检查。

新录制的可复用关键帧动作还会记录上臂和大腿的参考方向，切换模型时根据目标角色的方向修正对应关节；内置挥手也有平滑的参考姿态调整。独立播放器和 GLB 烘焙使用同样的求值规则。旧动作没有这些参考信息时保留原有行为，带模型专属通道的动作不会自动跨模型转换。小臂、小腿的独立参考轴、足部接地和衣物碰撞尚未自动校正。

## 调整映射

可在编辑器右侧展开模型映射，为语义骨骼和表情选取实际目标。对应数据也可在工程 JSON 的 `mappings` 中读取和调整。键是语义通道，值是模型里的目标名称。重新打开工程后应用，目标缺失时在模型能力中提示。

```json
{
  "mappings": {
    "local:example.glb": {
      "bones": { "rightUpperArm": "Arm_R" },
      "expressions": { "smile": "SmileShape" }
    }
  }
}
```

新模型先测试头颈、肘、腕和骨盆的单轴旋转，再检查位移和参考姿态。表情逐个拉动权重，确认实际网格变形范围和同名轮廓同步。需要同时组合口型时，优先验证 A 与张嘴通道是否为同一形态的替代通道。

## 本地交付和服样例

这两个样例未随应用打包，请从本机手动导入。内置和服仍是原有版本，表情只有张嘴。

| 模型 | 表情与动作 | 衣物和头发 |
| --- | --- | --- |
| 和服 GLB | 双眼、左眼与右眼闭合形态，以及 `SmallStepWalk`、`GentleGreeting`、`Blink` 三个原生动作。`Blink` 只驱动眼睑。 | 小步走和问候保留逐帧烘焙的裙摆形态及原有修正。两个全身片段重叠时互斥播放。 |
| 和服 VRM | 正式预设只有 `blink`、`blinkLeft`、`blinkRight`；另有可直接操控的原始面部形态键。无原生动作片段。 | 预览模拟文件自带的五条头发弹簧链。样例没有为这些链引用头发碰撞体，不能据此保证碰撞或穿模表现。 |

对于其他 VRM，实时弹簧和碰撞取决于模型实际声明的配置。可展开编辑器的「模型能力」查看弹簧关节与碰撞组数量。

原始资产情况见 [资源审计](ASSET_AUDIT.md)。
