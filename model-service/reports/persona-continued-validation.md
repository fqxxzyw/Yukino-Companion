# 0.4.0 本地人格续训与桌面离线验证

2026-10-25，实际训练与本机 CPU 推理已经执行。训练完成不代表人物还原通过人工验收；本次发现的错误一并保留。

## 训练对象与环境

- 基础模型：`Qwen/Qwen2.5-1.5B-Instruct`，固定 revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`。
- 初始权重：此前真正完成 87 步的知识 LoRA，继续更新同一个适配器；不是此前仅运行一次的性格 smoke 权重。
- 本轮：原创合成人格场景，62 个训练族 / 186 条训练样本，8 个验证族 / 24 条验证样本，另留 8 个测试族 / 24 条测试。每族三种上下文，按族切分；相近语义仍可能跨集合，不声称完全消除泄漏。
- 共享角色卡 v1.2.0，包 SHA-256：`ba2f17ab77272cc9e92c81aad5b762578b7c310159878756eccd5629085f13f4`。
- 云端 Linux 容器，没有 GPU；8 核 CPU 配额、8 GiB 内存上限。PyTorch 2.6.0+cpu、BF16。报告中的 `hardware.ram_gib` 是宿主机总内存，不能当成本容器可用内存。
- 完整一轮 / 47 个 optimizer step，batch 1、梯度累计 4、学习率 5e-5、序列上限 1024；实际最长样本 564 token。训练过程约 1364.98 秒，另有训练前后验证与导出。

24 条验证的 assistant-token loss 从 **3.63267350 降至 3.24914479**。这是这批合成目标文本的损失，不能解释为知识正确率、人格完成度或原作还原评分。完整机器报告见 `persona-continued-training.json`。

新 LoRA 权重 SHA-256：`21f347ebc4b8658705dfd601270955708814d37a18bf5272cd0bfa1878cfdb7b`。

## 实际发行格式

合并基础模型与新 LoRA，再转换和量化为 Q4_K_M，输出文件 `yukino-persona-q4_k_m.gguf`，**986,048,192 bytes**，SHA-256：`118ddd271a7fc2119a9e8140e2df7ad1d5e8cc84d2e18ca4344551747f0934a6`。

转换器 llama.cpp commit：`b3fa69955ea81c3b60e77e3c1e2224c4a826ffb9`；本机量化器为 llama-cpp-python 0.3.36。CI 若使用其他量化器实现，可能得到不同权重 hash，需要针对 CI 实际产物再次验证。CPU 与 GPU 使用同一份权重；本轮没有实际 GPU 硬件验证。

独立适配器包与本地模型包均不含小说全文、检索数据库、优化器状态或密钥。FP16 合并/转换中间文件不进入桌面发行目录。

## 真实桌面调用

`scripts/evaluate_desktop.cjs` 使用实际 `LocalChatService → desktop_worker.py → llama.cpp`，加载上述 GGUF、复用生产精简人物提示词，生成六个开发回归问题及完整 24 条保留测试。没有 API key、HTTP 模型服务或远程对话调用。

全部 30 个请求有真实回复，加载耗时 1.823 秒，首个完整人物提示词预填充与回复耗时 12.012 秒；后续短回复多为 0.2—1.5 秒。不同硬件、长回复和长历史不能套用这一速度。实际设备报告为 CPU、0 层 GPU offload；卸载后 ready 为 false。原始回答、上下文、耗时和结束原因见 `desktop-evaluation-v1.2.json`。

## 已发现的质量问题

| 回归点 | 实际表现 |
| --- | --- |
| 普通“你是谁”、姐姐姓名 | 自然第一人称介绍；姐姐回答雪之下阳乃；未主动追加数字人说明。 |
| 与八幡的关系 | 保留喜欢对方的关系，但错误说成“同班同学”。 |
| 明确询问真人或 AI | 承认自己是软件，但后半句“你不需要回答我是真人还是AI”语义别扭。 |
| 明确作品分析 | 编造了分手、兴趣与相处经过，并达到 192 token 上限被截断；不能作为可靠剧情分析。 |
| 未收到图片的保留场景 `daily_05-c` | 错说“收到啦”，违反实际输入边界。 |
| 其他保留场景 | 有空泛、答非所问、误解代词和只重复用户意图的回答；不等于完整人格验收通过。 |

六个开发问题有训练重叠，因此不作为盲测准确率。保留测试有独立场景族，但由同一套合成场景设计而来，也不能代表开放世界表现。没有使用词汇硬删除来掩盖失败，没有通过编造回答或替换成外部 API 来通过本地测试。后续提示词修正后的同题重测应记作开发回归，而不是新的独立保留测试。

## 冻结的生产提示与开发回归

本地 1.5B 模式使用同源 `training.md` 短人格，加上实际文字输入状态和简短人物事实；API 的完整/精简角色卡与可阅读的完整人物文档不变。没有改动已冻结的训练卡，没有重新命名权重，也没有在运行时硬替换模型输出。传给模型的用户原问题保留原样。

`desktop-regression-v1.2-r1/r2/r3.json`、`desktop-regression-v1.2-short-prompt.json` 与 `desktop-regression-v1.2-short-wrapper.json` 是保留的候选试验记录。最终生产代码的六条同题重测见 **`desktop-regression-v1.2-final.json`**；这些问题已经看过并用于调整提示词，全部属于开发回归，不能重新称为盲测。

最终重测仍有明显局限：身份直问能正常答“应用里的AI”；图片问题说“图片没传上来”，但先用了含混的“收到啦”接话；关系问题仍把不同班错说同班；剧情分析编造离校与关系细节；对“你其实很温柔呢”仍可能主动回答“我不会假装是真人”。因此，**不能宣称本地模型的主动身份说明、人物事实或完整性格问题已经全部修复**。当前可确认的是实际训练、权重导出、CPU 离线生成、设置/加载/卸载/取消与翻译衔接接口已实现；人格和知识质量需要后续更多数据与严格评估。
